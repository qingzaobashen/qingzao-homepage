# 2026-09-10

## AdSense 预检报告「找不到隐私政策」根因分析（docs/Ads/问题/审查1.md）

- 结论：隐私政策页面存在且正常（`/privacy` 200、含 Cookie 披露、含 AdSense 脚本、已进 sitemap）；Footer 组件也有 `/privacy`、`/terms` 链接（zh-CN.json 的 `footer.nav.legal.links` + `footer-legal` 两处）。
- 真正根因：**预渲染的静态 HTML 里没有 Header/Footer**。`scripts/prerender.mjs` 的 `buildStaticBodyHtml()` 只往 `#root` 注入手写正文片段（`static-prerender`），`buildPostHtml()` 同样只有面包屑。因此任何页面的原始 HTML 都没有导航栏和页脚 → 不执行 JS 的抓取工具看到的首页只有正文，没有任何指向隐私/关于/联系的链接。
- 验证：线上 `https://qingzao.site/` 原始 HTML 仅 4812 字节，`隐私` 出现 0 次，`class="footer"` 出现 0 次；`/privacy` 页面同样无 footer。检测工具报「首页 538 词」与静态片段规模吻合，说明它取的是未执行 JS 的 HTML。
- 附带发现：`buildStaticBodyHtml('/')` 仍在渲染**旧版工作室首页**文案（hero/products/about/contact），而 `App.jsx` 的 HomePage 早已改为 BlogHero/ReadingEntries/FeaturedSeries/CategoryBrowse/LatestPosts，静态内容与运行时内容已漂移。
- 修复方向：在 `prerender.mjs` 中为所有静态路由与博客页统一注入共享的 `<header>`/`<footer>` 静态片段（至少含隐私政策、服务条款、关于、联系链接），并同步更新首页预渲染文案。

## 静态 title/description 漂移核对结果（待修，用户已确认要修但尚未动手）

对比 `prerender.mjs` 的 `staticRoutes` 与各页面组件 `<SEO>`：

| 路由 | title | description |
|---|---|---|
| /products | ❌ 静态「产品」vs 组件 `t('productsPage.title')`「我们的产品」 | ❌ 不一致 |
| /about | ❌ 静态「关于我们」vs「关于青枣工作室」 | ❌ 不一致 |
| /contact | ✅ 一致（联系我们） | ❌ 不一致 |
| /privacy /terms /disclaimer /404 | ✅ 一致 | ❌ 不一致 |
| /blog | ✅ | 仅差一个句号，可忽略 |
| /editorial | ✅ | ✅ |
| / | ✅（已修） | ✅（已修） |
| /series | ✅（新增即对齐） | ✅ |

**反向漂移（该改组件而非 prerender）**：`PrivacyPage` / `TermsPage` / `DisclaimerPage` / `EditorialPage` / `NotFoundPage` 的 `<SEO title/description>` 硬编码中文，英文站（`/en/privacy` 等）运行时 Helmet 输出中文，而预渲染静态是英文 → 英文页也漂移。这 5 个组件需改用 `t()` 做国际化。
- 另：`/products` 一直未进 sitemap（`staticPages` 里没有），已在核对时发现，尚未改。

## 上述漂移已全部修复（同日）

1. **locale 新增 `seoDescription` 键**（zh-CN / en-US 各 5 处）：`legal.privacy/terms/disclaimer/editorial.seoDescription`、`notFound.seoDescription`。
2. **5 个页面组件的 `<SEO>` 改用 `t()`**：PrivacyPage / TermsPage / DisclaimerPage / EditorialPage（title 用 `legal.*.title`、desc 用 `legal.*.seoDescription`，并把 `const { localePath }` 改成 `const { t, localePath }`）、NotFoundPage（`notFound.title` / `notFound.seoDescription`）。此前这 5 页硬编码中文，导致英文站运行时标题是中文。
3. **`prerender.mjs` 的 `staticRoutes` 文案全部对齐组件**：products（我们的产品/Our Products）、about（关于青枣工作室/About Qingzao Studio）、contact（desc 改「我们随时欢迎您的反馈和建议」）、privacy/terms/disclaimer/404 的 description。
4. **sitemap 补 `/products`**：`staticPages` 加一行，URL 数 63 → 64。
5. **发现并统一「站点名后缀」漂移**：`SEO.jsx` 第 21 行 `fullTitle = ${title} - ${siteName}`（青枣工作室 / Qingzao Studio），但静态 HTML 没有后缀；而博客页又在 `main()` 里自己拼了后缀，导致「博客有、静态页没有」。修法：在 `injectHead()` 里**统一追加一次后缀**（`og:title` / `twitter:title` 同步），并删掉 `main()` 中博客的 `${post.title} - 青枣工作室` 拼接。现在 staticRoutes / 博客 / 系列只需传「不含后缀」的标题。

### 长期约定（重要）

- **标题唯一真源 = 页面组件的 `<SEO title>`（不含站点名后缀）**；`prerender.mjs` 里 `staticRoutes` / 博客 / 系列的 `meta.title` 必须与之逐字一致，**且都不要再手写「 - 青枣工作室」后缀**（由 `injectHead` 统一追加）。
- description 同理：`staticRoutes` 的 description 必须等于组件 `<SEO description>`，建议统一放 locale 的 `*.seoDescription` 键，避免再次漂移。
